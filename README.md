# PLK KPI 2570

ระบบติดตามตัวชี้วัดกระทรวงสาธารณสุข ปีงบประมาณ 2570 ของสำนักงานสาธารณสุขจังหวัดพิษณุโลก ระบบมี 3 ส่วน ได้แก่ แดชบอร์ดสำหรับผู้บริหารและผู้สนใจ หน้าบันทึกผลสำหรับผู้รับผิดชอบตัวชี้วัดของแต่ละกลุ่มงาน และหน้าผู้ดูแลระบบซึ่งจัดการได้ทุกส่วน

## ความสามารถหลัก

- ตัวชี้วัด 24 ตัว (34 รายการรวมตัวย่อย) ตามแผนงาน/โครงการ และตัวชี้วัด สธ. ปี 2570 พร้อมประเภทตัวชี้วัด (Health KPI, ตรวจราชการ, PA, 10 Flagship, 7 ONE) และเพิ่มประเภทได้
- สูตรคำนวณ: ร้อยละ, อัตราต่อพัน/หมื่น/แสน, สัดส่วน, จำนวน, เพิ่มขึ้น/ลดลงจากปีก่อน, เพิ่มขึ้น/ลดลงจากค่าเฉลี่ยย้อนหลัง N ปี, กรอกค่าผลลัพธ์ และประเมินผ่าน/ไม่ผ่าน
- ตัวชี้วัดย่อย: เลือกการนับในสรุปผล และเงื่อนไขการผ่านของตัวหลักได้
- ระดับจังหวัดและอำเภอ (เลือกทุกอำเภอหรือบางอำเภอ) แยกข้อมูลในสังกัด/นอกสังกัด สป.สธ.
- สีสถานะ เขียว / เขียว*** เฝ้าระวัง / เหลือง / แดง / เทา และระยะห่างจากเกณฑ์เป็นจำนวนคน (หรือหน่วยของตัวชี้วัด)
- “ข้อมูล ณ วันที่” รายตัวชี้วัดและรายรอบ, นำเข้าไฟล์รายงาน HDC (Excel/CSV), เลือกใช้ข้อมูล HDC หรือบันทึกเอง
- ส่งออกทุกหน้าเป็น PNG, PDF, Excel (.xlsx) และ Word (.docx)
- ลงทะเบียนผู้ใช้ → ผู้ดูแลอนุมัติตามกลุ่มงาน → บันทึกผลได้เฉพาะตัวชี้วัดของกลุ่มงานนั้น (เซิร์ฟเวอร์ตรวจสิทธิ์ทุกครั้ง)
- บันทึกประวัติการแก้ไขทุกครั้ง และสำรอง/กู้คืนข้อมูลจากหน้าผู้ดูแลระบบ

## ทดลองใช้บน GitHub Pages (ไม่ต้องติดตั้ง)

โฟลเดอร์ `docs/` เป็นเวอร์ชันทดลองที่ทำงานในเบราว์เซอร์ทั้งหมด ข้อมูลที่ทดลองบันทึกเก็บในเบราว์เซอร์ของแต่ละคนเท่านั้น ไม่มีการส่งข้อมูลไปที่ใด

1. สร้าง repository ใหม่บน GitHub แล้วอัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ (หรือใช้คำสั่งในหัวข้อ “นำขึ้น GitHub” ด้านล่าง)
2. ไปที่ **Settings → Pages** เลือก **Source: Deploy from a branch**, **Branch: main**, โฟลเดอร์ **/docs** แล้วกด Save
3. รอประมาณ 1 นาที เปิดลิงก์ `https://<ชื่อบัญชี>.github.io/<ชื่อ repository>/`
4. ใช้ช่อง “บทบาท” มุมขวาบนสลับดูในฐานะ ผู้ดูแลระบบ / ผู้รับผิดชอบ / ผู้ใช้ใหม่ / ผู้เยี่ยมชม และกด “ล้างข้อมูลทดลอง” เพื่อเริ่มใหม่

> หมายเหตุ: GitHub Pages ของบัญชีฟรีต้องเป็น repository แบบ Public จึงจะเปิดได้ ไม่ควรใส่ข้อมูลจริงในเวอร์ชันทดลอง

## ติดตั้งบนเซิร์ฟเวอร์ของหน่วยงาน

ระบบเป็น Node.js ไฟล์เดียว ไม่ต้องติดตั้งแพ็กเกจเพิ่ม ใช้ฐานข้อมูล SQLite ที่เก็บเป็นไฟล์เดียวในโฟลเดอร์ `data/`

### วิธีที่ 1: Docker (แนะนำ)

ต้องมี Docker และ Docker Compose บนเซิร์ฟเวอร์

```bash
# 1) แก้รหัสผ่านผู้ดูแลระบบในไฟล์ docker-compose.yml (ADMIN_PASSWORD)
# 2) สร้างและเริ่มระบบ
docker compose up -d --build
# 3) เปิด http://<ที่อยู่เซิร์ฟเวอร์>:8080 แล้วเข้าสู่ระบบด้วย admin / รหัสที่ตั้งไว้
```

ดูบันทึกการทำงาน: `docker compose logs -f` · หยุดระบบ: `docker compose down` · ข้อมูลอยู่ที่ `./data/plk-kpi.db`

### วิธีที่ 2: Node.js โดยตรง

ต้องมี Node.js 22.13 ขึ้นไป (Windows ใช้ตัวติดตั้งจาก nodejs.org ได้)

```bash
# Linux / macOS
ADMIN_PASSWORD='ตั้งรหัสผ่านที่ปลอดภัย' npm start

# Windows (PowerShell)
$env:ADMIN_PASSWORD='ตั้งรหัสผ่านที่ปลอดภัย'; npm start
```

ถ้าไม่ได้ตั้ง `ADMIN_PASSWORD` ตอนเริ่มครั้งแรก ระบบจะสุ่มรหัสผ่านแล้วแสดงในหน้าจอ (log) ให้เปลี่ยนรหัสหลังเข้าสู่ระบบ

ให้ทำงานตลอดเวลาบน Linux ใช้ systemd หรือ pm2 ได้ เช่น `pm2 start server/server.js --name plk-kpi --node-args="--disable-warning=ExperimentalWarning"`

### ค่าตั้งค่า (environment variables)

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `PORT` | 8080 | พอร์ตของเว็บ |
| `DATA_DIR` | `./data` | โฟลเดอร์เก็บฐานข้อมูล ต้องสำรองโฟลเดอร์นี้ |
| `ADMIN_USERNAME` | admin | ชื่อผู้ดูแลระบบคนแรก (สร้างตอนเริ่มครั้งแรกเท่านั้น) |
| `ADMIN_PASSWORD` | สุ่ม | รหัสผ่านผู้ดูแลระบบคนแรก |
| `PUBLIC_READ` | 1 | 1 = ดูแดชบอร์ดได้โดยไม่ล็อกอิน · 0 = ต้องล็อกอินก่อน |
| `ALLOW_REGISTER` | 1 | 1 = เจ้าหน้าที่สมัครบัญชีเองได้ · 0 = ผู้ดูแลต้องสร้างให้ |
| `COOKIE_SECURE` | 0 | ตั้ง 1 เมื่อเปิดใช้ผ่าน HTTPS |
| `TRUST_PROXY` | 0 | ตั้ง 1 เมื่ออยู่หลัง nginx/Apache |

### เปิดใช้ผ่าน HTTPS (แนะนำเมื่อใช้งานจริง)

ตั้ง nginx เป็น reverse proxy แล้วตั้ง `COOKIE_SECURE=1` และ `TRUST_PROXY=1`

```nginx
server {
  listen 443 ssl;
  server_name kpi2570.example.go.th;
  # ssl_certificate ... ; ssl_certificate_key ... ;
  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;          # สำหรับการอัปเดตข้อมูลแบบเรียลไทม์
  }
}
```

### การสำรองข้อมูล

- ทางหน้าเว็บ: ผู้ดูแลระบบ → ประวัติและสำรองข้อมูล → ดาวน์โหลดไฟล์สำรอง (.json) และกู้คืนจากไฟล์ได้
- ทางเซิร์ฟเวอร์: คัดลอกโฟลเดอร์ `data/` เป็นประจำ (ควรหยุดระบบก่อนคัดลอก หรือใช้ `sqlite3 data/plk-kpi.db ".backup backup.db"`)
- ไฟล์สำรองมีข้อมูลบัญชีผู้ใช้ (รหัสผ่านเข้ารหัสแบบ scrypt) ควรเก็บในที่ปลอดภัย

### อัปเดตเวอร์ชัน

แทนที่ไฟล์ในโฟลเดอร์ `public/` และ `server/` ด้วยเวอร์ชันใหม่ แล้วเริ่มระบบใหม่ (`docker compose up -d --build`) ข้อมูลใน `data/` ไม่ถูกแตะต้อง

## การใช้งานครั้งแรก

1. เข้าสู่ระบบด้วยบัญชีผู้ดูแลระบบ แล้วกด “เปลี่ยนรหัสผ่าน”
2. ผู้ดูแลระบบ → ตั้งค่า: ตรวจรอบรายงาน วันที่ตัดข้อมูล รายชื่อกลุ่มงาน และรหัสหน่วยบริการนอกสังกัด สป.สธ.
3. ผู้ดูแลระบบ → ตัวชี้วัด: ใส่ค่าเกณฑ์ตาม KPI Template ปี 2570
4. แจ้งเจ้าหน้าที่ให้สมัครบัญชีและลงทะเบียนขอสิทธิ์ แล้วอนุมัติที่ ผู้ดูแลระบบ → ผู้ใช้งานและสิทธิ์
5. ตั้งผู้ดูแลระบบสำรองอย่างน้อยอีก 1 คนในส่วน “บัญชีผู้ใช้”

## โครงสร้างไฟล์

```
public/            หน้าเว็บ (ใช้ทั้งเซิร์ฟเวอร์และเวอร์ชันทดลอง)
  index.html       แอปทั้งหมด
  shim.js          ตัวเชื่อมแอปกับเซิร์ฟเวอร์ (หรือ localStorage ในโหมดทดลอง)
  rules.js         กติกาสิทธิ์การอ่าน/เขียน ใช้ร่วมกันระหว่างเซิร์ฟเวอร์และโหมดทดลอง
  seed.json        ตัวชี้วัด 34 รายการและค่าตั้งต้น ใช้ตอนเริ่มระบบครั้งแรก
  vendor/          ไลบรารีส่งออกไฟล์ (html2canvas, jsPDF, SheetJS, docx) ทำงานได้โดยไม่ต้องต่ออินเทอร์เน็ต
server/server.js   เซิร์ฟเวอร์ (Node.js 22+, SQLite ในตัว)
docs/              เวอร์ชันทดลองสำหรับ GitHub Pages (สร้างใหม่ด้วย npm run build:demo)
```

ฟอนต์ภาษาไทยโหลดจาก Google Fonts ถ้าเซิร์ฟเวอร์ไม่มีอินเทอร์เน็ต หน้าเว็บจะใช้ฟอนต์ของเครื่องแทนโดยอัตโนมัติ
